# Splitwise expenses paid by others: Monarch imports

Use this mode when the user asks to track personal expenses paid by somebody else and recorded in Splitwise. A request for one example stays limited to one source expense. Saved Splitwise allocations establish the user's share; ask only when payer, identity, currency, purpose or allocation conflicts with evidence.

## Read the source

Find the actual person in saved contacts. Inspect recent activity to establish who added the expense and when; opening an old expense or editing one today does not mean it was added today. Open the saved expense and record its stable ID/link, title, currency, expense date, added date, payer(s), user's owed/paid shares, comments and attachment. A friend adding an expense does not prove that friend paid it. Import only the portion somebody else paid on the user's behalf, excluding any portion already charged to the user's bank/card.

Inspect an attached receipt when available. Preserve saved rounding. Distinguish an itemized merchant receipt from a bank screenshot, and document gaps in items, tax or final posting. A tip comment may explain a difference; calculate it in cents, do not add it again to a saved total that already includes it. If no merchant receipt exists, a clear Splitwise record can support an explicitly labeled source-based import; do not invent itemization or claim the payer's bank charge is verified as posted.

Use a verified purchase/service date when known, otherwise the saved expense date; separately note the added date. A today-only selection uses the user's timezone and activity timestamps. Do not silently convert currency or use the full group bill as the user's expense.

## Prevent duplicate spending

Search Monarch across all accounts and review states for the exact Splitwise expense ID/link, then purchase/merchant/title variants, nearby dates and the user's exact amount. Inspect plausible manual entries, combined entries, synced bank charges and split portions; exact amount alone is not identity. Update an existing matching import within scope instead of creating another. If the user's own bank transaction already represents the purchase, reconcile it rather than importing it twice.

Check whether a bank settlement already includes the source expense and is counted as spending. Match payer, timing and covered expenses; do not infer coverage from amount alone or the current net friend balance. If the same spending is already captured, propose the linked reclassification or replacement before creating a duplicate. Keep older settlements and unimported historical spending unchanged unless the user authorizes a bounded migration. Record unresolved settlement coverage rather than claiming all historical duplication has been eliminated.

## Account and category

Reuse an appropriate dedicated manual Splitwise tracking account when present. Otherwise, an authorized import can include setting up a clearly named bookkeeping-only manual account, using supported transaction-capable account types. Explain its purpose and scope. Never add the expense to a real synced bank/card that did not pay it, connect another financial institution, or imply a partial import account equals the complete Splitwise balance. A partial tracking account should be excluded from net worth where supported; do not seed it with a guessed full debt or receivable balance. Preserve the chosen account model and balance-update behavior, and verify whether a manual transaction changes its balance before claiming a liability is tracked.

Categorize by the underlying purchase using existing Monarch categories: groceries, restaurants, delivery, household supplies, transit, rides or similar. Do not use Friends for the user's own consumed share merely because someone else paid. Prefer a sufficiently specific existing category; resolve ambiguity or mixed-category personal shares before saving when it materially affects tracking. Split only the user's share when supported by evidence, with exact cents summing to that share. Do not create new categories unnecessarily.

## Settlement treatment

Once the personal share is recorded as an expense, its later repayment is a transfer/settlement against the tracking account, not another purchase. Reconcile the corresponding manual-account side as appropriate to the account model. A repayment may cover both imported and unimported expenses: separate only verified covered amounts, retain unimported spending under its established treatment, and leave unresolved portions for a decision. Netting against amounts friends owe the user is not a refund or income. Do not retroactively reclassify all Splitwise settlements or existing custom categories as part of one example.

## Save and verify

Create a manual expense for the exact personal share, with the underlying merchant in the description and the existing purchase category. Mark reviewed only when authorized; report the saved state. Keep the original Splitwise financial record unchanged unless separately asked.

Use short labeled notes with applicable fields:

Imported personal share; paid by another person in Splitwise.
Purchase: [items/service; purchase date]. Added to Splitwise: [date].
Payer: [saved name]; full bill: [currency and total].
Saved shares: You [amount]; payer/other participants [amounts relevant to explaining the split].
Monarch expense: [your amount] under [category]; manual account [name].
Fees/tax/tip/rounding: [verified treatment; identify gaps].
Splitwise expense ID: [stable ID]
Source: [expense link]; attachment: [type/link, if available].
Settlement: [verified coverage or unresolved status]; do not count repayment of this imported share as spending again.

Reload Monarch and reopen the exact new entry. Verify a single saved source ID, personal amount/sign/currency, category, date, manual account, source note, balance behavior and review state. Confirm that a retry did not create another copy. Report the source title, personal amount, category, account, date and any remaining limitation. Keep actual account records and personal examples out of public skill files.
